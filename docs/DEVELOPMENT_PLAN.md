# 开发路线 / Development roadmap

## 当前基线

0.2.0 候选已实现 `exam-v2`／`assessment-v4`、四结构题集、逐题证据、稳定历史管理与离线图文手册。考试专用校准工具和模拟在合成环境验证完整流程。真实研究按确切型号、家族、请求设置及卷型独立冻结，付费采样需单独预算，支持状态仍为实验性。

独立工作台、CLI、Python API v2 和本机只读用量观察已经可用。评估 `assessment-v4` 提供单侧和同题对照、按家族选题、重试与预算、匿名历史及 HTML 导出。Windows x64 便携候选已完成本地构建和固定离线 worker 冒烟。macOS、Linux 与 Windows Setup 由独立的原生构建工作流验证。

| 阶段 | 交付门槛 |
| --- | --- |
| 提高基础检测质量 | 用模拟故障和复现种子验证两侧的题目计数、重试、取消、预算和报告一致性。 |
| 真实校准 | 先选确切 GPT/Codex 型号及受控替代，按冻结协议在多个日期完成先导和验证。分别公布误报、检出、无法判断和开销。 |
| 扩大家族与平台覆盖 | 按家族验证题型和协议，标清连接、可基础评测、匹配参考、真实校准四种状态。各平台分别验收启动、安装与卸载。 |
| 接回 Token 监视器 | 在上游单独提交集成分支，先以合成 v2 快照验收只读展示，再审阅显式启动检测和预算。 |

0.2.0 的 `exam-v2` 为 GPT/Codex 和 DeepSeek 提供可选 120 或 180 题的手动考试。使用合成数据验收评分、交卷、预算和报告。真实校准按家族和卷型独立进行，需另行授权及预算。[能力考试方法](METHODS.md#capability-exam--能力考试)

实验性结论只适用于实际测试的任务和条件。只有经过独立复核的真实试验可支持「已校准」标记。真实采样需要单独授权和预算。 [方法](METHODS.md)

## 下一阶段：先导证据与选题诊断

在真实校准前，先完善现有 `calibration-report` 的离线检查。

1. 从冻结清单重建先导试卷，逐项核对题号、种子、题型、模板、难度和答题侧，拒绝错误配对。旧记录缺少逐题证据时明确标记不可用。
2. 按模板与难度输出计划配对、有效配对、未知、双方都对／都错、官方单侧答对与反向改善；格式失分计零、连接故障保持未知，重试不增加题数。
3. 分差用于描述先导数据，保留覆盖率与试验数；不自动淘汰模板、不改已确认题集、不新增“已校准”结论。通过合成错误证据、缺失及故障样例验收后，再单独安排真实采样。

## 未来上游集成

1. 以经过验证的独立提交为基准，记录提交哈希、检测器版本和 API 版本。
2. 从 Token 监视器当前主分支建立独立的集成分支，将所需模块同步到其检测子目录并保留 MIT 版权声明。
3. 通过 `Auditor.snapshot()`、`Auditor.usage_snapshot()` 或随机会话的 `GET assessment`、`GET usage` 读取匿名 v2 数据。主采集器保持原有离线与只读边界，主应用不接触检测器的专用 Key。
4. 测试旧报告、未知来源、缺失用量与官方登录分组。确认业务、中转探针和官方参考各自计量后，再按上游规则提出合并。 [接口说明](EXTENDING.md#integration-contract--token监视器接入)
